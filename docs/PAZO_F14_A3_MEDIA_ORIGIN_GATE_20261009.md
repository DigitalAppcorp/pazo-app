# PAZO F14 A3 — Media origin / CDN preflight (not deployed)

**Evidence source:** Supabase Storage docs for [Delete Objects](https://supabase.com/docs/guides/storage/management/delete-objects) and [Purge CDN Cache](https://supabase.com/docs/guides/storage/cdn/purge-cdn-cache), checked on 2026-10-09.

- Supabase documents that physical files must be deleted with the **Storage API**. Direct SQL DELETE against `storage.objects` leaves orphaned bytes and is prohibited.
- Existing buckets are `pet-avatars`, `post-photos`, `community-avatars`, `community-post-photos`, `pet-documents`. Verify exact object id/path, object version and ALL references, never infer filename ownership from URL alone; do not delete if shared with another account.
- Smart CDN invalidates cached objects upon change/deletion, but manual immediate `purgeCache` is documented as requiring **Pro Plan or above** and a secret key. **No upgrades** under PO cost policy; manually purge CDN only if later explicitly approved and needed. This means a zero-upgrade release must verify user-visible old links and allow honest cache propagation instead of guaranteeing instantaneous revocation.
- `src/features/account/mediaManifest.ts` is **pure, never invokes remove()**, checks allowlisted buckets, traversal/encoded-path threats, object and owner verification, shared references, write-freeze evidence, lease and duplicates. It **always returns deletionAuthorized=false**. Follow-up removal-verification helper requires origin missing, old public URL unavailable, no row reference and CDN check, still never authorizes Auth deletion.
- After explicit backend and application gate, a separate server worker will use Storage API `storage.from(bucket).remove([exactPath])` on individually verified object paths and persist outcome. It must re-check fresh DB object ownership, matches and no shared refs in a frozen transaction before each call, record retries and verify origin and public URL after removal.
- QR, rescue, location pictures, legacy avatar URLs, community photos and private documents must be checked. A post hidden by RLS can still have public Storage URL. No CDN/backup or Auth cleanup is implemented by this plan.
- QA requires test exact path, version changed, shared path, object already removed, Storage timeout, 404 after deletion, cached link still available, SQL orphan, retry idempotency; never declare verified while any URL/storage item remains.
